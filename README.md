# Flipkart Product Search Automation

A UI automation project built with **Java, Selenium WebDriver, TestNG, and Gradle** to test product searches and extract information from Flipkart.

The project passed its platform assessment and is maintained in GitHub.

## Test scenarios

| Test | Scenario | Output |
| --- | --- | --- |
| `testCase01` | Search for **Washing Machine**, sort by popularity, and read product ratings | Count products rated **4 stars or lower** |
| `testCase02` | Search for **iPhone** and read product discounts | Print titles and discounts of products with **at least 17% off** |
| `testCase03` | Search for **Coffee Mug**, apply the **4 stars & above** filter, and read rating/review information | Print up to five products ranked by the count extracted from the selected rating/review element, including titles and image URLs |

> The mug extraction currently parses the first number in the selected rating/review text. If that text contains both ratings and reviews, confirm that the locator targets the intended count before interpreting the ranking as review count.

## Implementation highlights

- Reusable wrappers for searches, clicks, and product data extraction.
- Explicit waits for dynamic page content.
- Stale-element handling where results refresh during extraction.
- Native Selenium text reads and browser interactions.
- ChromeDriver command logs for troubleshooting and platform assessment.
- Assertions to report failed extraction operations.

## Prerequisites

- JDK 17
- Google Chrome
- Git
- Internet access to Flipkart and dependency repositories

Use the Gradle wrapper included in the repository; a separate Gradle installation is not required. ChromeDriver must be compatible with the installed Chrome version. Selenium Manager can resolve the driver when supported by the environment.

## Setup

1. Clone this repository using its GitHub clone URL.
2. Open the cloned project directory.
3. Confirm that `src/test/resources/testng.xml` selects `demo.TestCases`.
4. Run the tests using the commands below.

## Run the tests

From Git Bash, macOS, or Linux:

```bash
./gradlew clean test --console=plain
```

From Windows PowerShell:

```powershell
.\gradlew.bat clean test --console=plain
```

To save console output in Git Bash:

```bash
./gradlew clean test --console=plain > test-run.txt 2>&1
```

To run tests and generate the Checkstyle report:

```bash
./gradlew clean test checkstyleTest --console=plain
```

## Reports and logs

After execution, inspect:

- **Test report:** `build/reports/tests/test/index.html`
- **Test result XML:** `build/test-results/test/`
- **ChromeDriver log:** `build/chromedriver.log`
- **Checkstyle XML:** `build/reports/checkstyle/test.xml` when generated by the configured Checkstyle task

## Platform assessment

In the original assignment environment, run the provided assessment script after generating the test results and logs:

```bash
./run_platform_assessment.sh
```

The assessment checks code-quality requirements and recorded browser actions, including navigation, search input, and product text extraction. The platform assessment has passed for this project; this does not guarantee that future runs will pass against changing live-site content.

## Maintenance notes

Flipkart is a live website. Product availability, discounts, page structure, and generated CSS classes can change. If a test fails:

1. Check the console output and test report for the first failure.
2. Inspect the current product HTML and update affected locators.
3. Use explicit waits and re-locate elements when the results refresh.
4. Confirm that ratings and review counts are parsed from the intended fields.

A product search may return no items meeting the discount threshold. Successful extraction and the presence of qualifying products are separate outcomes.

## Learning outcomes

This project provided practical experience with browser automation, reusable test utilities, dynamic page synchronization, XPath and CSS locators, product data parsing, and diagnosing failures through browser command logs.
